# 动作与神情原型

这是一个独立的浏览器原型，用 [MediaPipe Tasks Vision](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker) 的 **Pose Landmarker** 和 **Face Landmarker** 观察演讲视频里的身体动作和面部/头部信号。

它**不进入**正式评分，也不改动 `score.js`。目的是先回答一个问题：这些信号在真实演讲视频上能不能稳定测出来、测出来的数有没有用。

## 怎么打开

在仓库根目录跑一个静态服务器：

```sh
python -m http.server 8781 --directory docs
```

然后打开：

```text
http://127.0.0.1:8781/prototype/
```

端口被占用时换一个数字即可。

也可以直接部署到 GitHub Pages 后访问 `/prototype/`。不要用 `file://` 直接打开，ES module 和 WASM 会被浏览器拦住。

## 它测什么

**身体动作**

- 人体检测率
- 手势幅度：手腕移动速度 / 肩宽，单位「肩宽/秒」
- 手势次数：明显手腕动作，次/分钟
- 身体晃动：肩中点移动速度 / 肩宽
- 倾斜：肩中点相对髋中点的水平偏移，% 肩宽
- 手高于肩的帧占比
- 肩线倾斜角度

**面部与头部**

- 人脸检测率
- 微笑强度与微笑占比（blendshape）
- 抬眉强度、张嘴程度
- 眨眼频率（采样率低，只作参考）
- 头部左右偏移：鼻子相对两眼中点的偏移，% 眼距
- 头部俯仰偏移：相对本人中位姿态的偏移，% 脸高
- 头部侧倾角度
- 朝前占比：左右/俯仰/侧倾都较小的帧占比
- 表情变化：微笑强度的标准差

## 限制

- 采样率约 1–2 帧/秒，快速手势和眨眼会漏。
- 头部角度是从人脸关键点估的近似值，不是精确的头部姿态；镜头角度、焦距和畸变都会影响。
- 「朝前占比」不是眼动仪，不能证明在看镜头。
- 表情受文化、个人风格、疲劳影响；不要用微笑多少判断真诚。
- 模型文件从 CDN / Google Storage 下载（约 9.5 MB，WASM 另计），第一次打开需要联网；视频本身只在浏览器里处理，不会上传。
- 人物太小或不是单人口播时会测不准：屏幕录制、多人缩略图、远景这些画面里，人脸可能只有几十像素，模型找不到。肩宽不到画面宽度 5%，或脸宽不到 8% 时，对应指标显示 `–`，页面会给警告。
- 看不到的部位不猜：手腕不在画面里时，手势幅度、手势次数和「手高于肩」显示 `–`；髋部不在画面里时，「倾斜」显示 `–`。不要把 `–` 读成 0。
- 分辨率不是唯一限制。360p 但人物占画面大，通常比 4K 但人物只占一个小角更好。建议人物占画面 1/3 以上，脸宽至少 8% 画面宽。
- 浏览器解不了的编码（例如部分 HEVC）会直接读不到画面；mp4 / mov / webm 最稳。
- 这是原型，不是测量仪；单个指标不能判断演讲好坏。

## 这次试了三个样本

以下是一次运行结果，不是准确率验证；没有人工标注，不能算 precision/recall。

| 样本 | 人体 | 人脸 | 结果 |
| --- | --- | --- | --- |
| `talkcamera.mp4`（1280×720，125s） | 100% | 98% | 手势、晃动、肩线、微笑、头部都有数；无警告 |
| `student_michael.mp4`（1280×720，120s） | 93% | 91% | 手腕在画面外，手势三项显示 `–`，有警告；晃动/倾斜/肩线可用 |
| `zoom_lecture.mp4`（1280×720，122s） | 14% | 0% | 屏幕录制 + 小摄像头缩略图，全部指标 `–`，有警告 |

结论：**单人口播、人物占画面较大时可用；屏幕录制、多人缩略图、远景不可用。** 这不是模型坏了，是画面里没有足够像素。

## 文件

- `index.html` — 页面
- `prototype.js` — 视频采样、MediaPipe 调用、指标计算
- `prototype.css` — 仅这个原型的样式

## 依赖

- `@mediapipe/tasks-vision@1.2.3`（CDN ES module）
- `pose_landmarker_lite` 模型
- `face_landmarker` 模型

版本固定在 URL 里；升级时同时改 `prototype.js` 里的 `WASM_BASE` 和 import。
